# Project instructions — Digital Library Archive

Persistent instructions for any automated or AI coding assistant working on
this repository. Read this file in full before making changes.

## Git commit rules (mandatory, project-wide)

These rules apply to every commit, in every phase, with no exceptions.

1. Commit **only** with the repository owner's existing, already-configured
   Git identity. Never change, override or work around `user.name`,
   `user.email`, the author or the committer (no `-c user.*`, `--author`,
   `GIT_AUTHOR_*`/`GIT_COMMITTER_*` variables or config edits).
2. Never reference Claude, Anthropic, artificial intelligence, AI-generated
   code or AI assistance anywhere in commit metadata. That covers titles,
   descriptions, trailers, co-author fields, and author or committer names
   and e-mails. In particular, never add:
   - `Co-Authored-By: Claude …`
   - `Generated with Claude Code`
   - `Generated by AI`
   - any other automatic attribution footer.
3. Never impersonate another contributor.
4. Never modify global Git configuration or disable security hooks (for
   example `--no-verify` or `commit.gpgsign` overrides) to satisfy these rules.
5. **Owner decision (Option B): never commit in cloud or automated
   environments.** Do not set or change any Git identity or signing setting
   there, whether global or repository-local, and never create commits signed
   with a non-owner key. Deliver every phase as:
   - a binary-safe patch against the owner's **verified, committed** result
     of the previous phase (never assume uncommitted cloud work was merged);
   - a commit script that the owner runs locally. It must refuse to run on
     an unexpected base commit, a wrong branch or a dirty working tree;
     verify the patch checksum; never pass identity or signing options; never
     rewrite history; and verify the resulting tree hash and commit metadata.
6. After each commit (run by the owner), its metadata is verified with:
   ```
   git log -1 --format=fuller
   git cat-file -p HEAD
   ```
7. Use conventional, professional messages, for example:
   `feat: add user authentication`, `fix: prevent duplicate ISBN records`,
   `test: add catalogue validation tests`, `docs: …`, `chore: …`.

## Architecture conventions

- PHP 8.4 runtime (code must also run on PHP 8.3 for local tooling; avoid
  8.4-only syntax such as property hooks). `declare(strict_types=1)` in every
  file. PSR-4 under `DigitalLibrary\` in `src/`.
- No frameworks and no new runtime Composer dependencies without a clear
  justification documented in `ARCHITECTURE.md`.
- Wire services explicitly in `src/Core/Services.php`. Register routes in
  `config/routes.php` with middleware aliases (`auth`, `guest`,
  `can:<permission>`).
- **Database:** PDO prepared statements only, never string-concatenated user
  input. Wrap multi-step writes in `Database\Transaction::run()`. Schema
  changes go in a **new** migration file
  (`database/migrations/YYYY_MM_DD_HHMMSS_name.sql`); never edit an applied
  migration. The runtime DB account has no DDL rights.
- **Database engine:** production is MariaDB 11.4 LTS (`mariadb:11.4.x-noble`,
  never `-ubi`): the production CPU (Pentium E5300, no SSE4.1/SSE4.2/POPCNT)
  cannot run MySQL 8.4 images (x86-64-v2). MySQL 8.4 stays supported and
  tested (CI `test-mysql`). Write SQL that runs unchanged on both: no
  `INSERT ... AS alias`, no optimizer hints, no JSON operators, no stored
  generated column returning a `CHAR` column. Engine differences live only
  in `Database\Engine` (positive MariaDB detection, `boundedSelect()`,
  error codes); tests must hold on both engines, never skip one. If a
  released migration cannot run on MariaDB, add an override with the same
  name in `database/migrations/mariadb/` (only a `-- ` header and
  documented replacements, pinned in `MigrationFilesTest`); never edit the
  released file and never rewrite `schema_migrations`. Backups restore only
  into the same engine. Keep the CPU-baseline CI check passing for every
  image change (ARCHITECTURE.md, "Production database").
- **Authorization:** every state-changing controller action must check
  permissions server-side, including object-level checks through
  `Security\Authorizer`, not just the route guard.
- **Output:** escape everything in templates with `$view->e()` / `$view->t()`.
  No inline `<script>` or `style=""` (the CSP forbids them).
- **Text:** every user-facing string is a translation key present in
  `lang/en.php`, `lang/es.php` **and** `lang/gl.php` (a test enforces parity).
- **Forms:** include `<?= $view->csrfField() ?>` in every POST form.
- **Audit:** record security-relevant and catalogue-changing actions with
  `AuditLogger::log()`. Never pass secrets in details.
- Keep ISBNs normalised through `Catalogue\Isbn` (ISBN-13 is the duplicate key).
- **Catalogue layering:**
  - Controllers handle HTTP, permissions and audit.
  - `Catalogue\Input\*` parse and validate request data.
  - `Catalogue\BookService` runs multi-table writes in one transaction.
  - `Catalogue\Repository\*` hold all SQL.
  - Dynamic SQL must bind every value through `Database\Params` (unique
    placeholder names; `Params::likeContains()` for LIKE).
- Record-level checks: `Authorizer::canEditRecord()` for works and editions
  (by `created_by`), `Authorizer::canManageCopy()` for copies (by owner).
  Assigning a copy to another owner requires `copy.manage_any`.
- Templates: reuse `templates/partials/*` (`input`, `select`,
  `tree_options`, `people_fields`, `cover`, `pagination`). Partials receive
  only the data passed to them. Use `$view->trans()` (unescaped) only when
  the value goes into a partial or helper that escapes it.
- **Edits of works, editions and copies are optimistic-locked:** forms
  carry `row_version`, and repository `update()` methods take the expected
  version and return false on conflict (throw `EditConflictException` from
  services). Any new edit form for these records must do the same.
- **Outbound HTTP** only through `Metadata\Http\HttpClient` (production:
  `CurlHttpClient` + `OutboundPolicy`). Never build request URLs from user
  input. Tests must use `Tests\Support\FakeHttpClient` and must not touch
  the network.
- ISBN-assisted entry: ISBN messages come from `Isbn::problem()`; keep the
  browser copy in `app.js` in step (`IsbnEntryAssetsTest`). Lookups run only
  on the explicit "Look up book" GET, never on POST or in the new-edition
  form (cache only: `lookup(..., network: false)`); no background/JSON
  lookup endpoint. `MetadataReview` reports provider values, it never
  invents or combines them. Existing-work suggestions never merge records.
  Provider backoff only through `Backoff\ProviderBackoff` (429 and
  500/502/503/504, bounded, never sleeps in a request); tests use
  `Tests\Support\InMemoryBackoffStore`.
- Administrative account changes go through `Auth\UserAdministration`
  (lock-out safeguards).
- Loans change `copies.status` only through `Loans\LoanService` (copy lock,
  one active loan per copy via the `active_copy_id` unique index); never set
  `on_loan` from other code. Copies with loan history are withdrawn, not deleted.
- Wishlists are owner-only (no admin override; others get 404) and are not
  audited. Collections are `private` or `shared` only; never add anonymous or
  public access without an explicit owner decision.
- The audit-log viewer is read-only: never add write routes or repository
  write methods; keep queries bounded (date range, indexed filters, keyset
  pagination) and escape/redact everything shown.
- Invitations: store only `InvitationToken::hash()`; show a raw link only
  in the response that created it; never put tokens or links in sessions,
  flashes, redirects, logs or the audit log; never allow the admin role.
  Pages with forms must keep the `same-origin` referrer policy
  (`no-referrer` makes browsers send `Origin: null`, which CSRF refuses).
- Exports: personal data only for the signed-in user (no user parameter);
  never export credentials, sessions, invitations, login attempts, the audit
  log, wishlists, loans or private collections in the catalogue export;
  stream with keyset batches; CSV cells go through `CsvWriter`.
- CI (`.github/workflows/ci.yml`): keep `contents: read`, actions pinned to
  full commit SHAs with a version comment, no secrets or
  `pull_request_target`, and no `! cmd` in `run` blocks (it never fails a
  `set -e` script). New shell scripts and Dockerfiles must be added to the
  shellcheck and `docker build --check` steps (`CiWorkflowTest` enforces it).
- Production stack: `docker-compose.prod.yml` (never the development file).
  Keep its guarantees, which `tests/Unit/Deployment/` enforces: only nginx
  is published (one port, explicit `DLA_HTTP_BIND`/`DLA_HTTP_PORT` with no
  defaults; never PHP-FPM or MariaDB), internal app/database networks,
  non-root read-only containers, image pins with digests, `APP_ROLE=web`
  containers without migration or root credentials. Ingress reuses the
  owner's existing Cloudflare Tunnel (cloudflared systemd service on the
  Docker host): never add a cloudflared service or tunnel, and keep nginx
  bound to loopback. The only trusted peer is `DLA_EDGE_GATEWAY` (the `edge`
  network gateway); never hardcode the port, subnet or gateway as production
  facts (they are owner-checked candidates). The Raspberry Pi is not part
  of the project.
- Persistent storage (Phase 5C, owner-confirmed split layout): system SSD
  working tree `/opt/digital-library`, code and configuration only
  (checked out with `--work-tree` from the bare repository
  `/home/brais/git/digital-library.git`; no `.git`, no nested `app/`;
  repository root = Compose project directory = build context); system SSD
  data root `DLA_DATA_ROOT=/opt/digital-library-data` (`mysql/`,
  `secrets/`, `mysql-init-guard/`), never inside the working tree; storage HDD
  `DLA_STORAGE_ROOT=/mnt/bravina-shared/digital-library` (UUID
  `ad62670f-861d-47a4-a68d-967272d27866`; `covers/`, `backups/`,
  `storage/`; `books/` reserved, not created or mounted). Never
  `/mnt/dockerdata`, never named volumes. Keep the ignore patterns as
  defence in depth (`.dockerignore` without `!` exceptions; Dockerfiles
  copy explicit paths only, never `COPY .`). systemd runs only the
  root-owned installed preflight `/usr/local/sbin/digital-library-preflight`,
  never a script from the user-writable working tree. Every data mount is a long-syntax bind with
  `create_host_path: false`; neither root has a Compose default. Database
  data only in db, backups only in ops. `docker/mysql/db-guard.sh` (db
  entrypoint) never lets MariaDB initialise an empty database without the
  owner's first-deployment authorisation, and never starts a data directory
  without `.dla-init-complete` (written last by the init script) or with
  MySQL 8 files; the preflight's mode
  (`--first-deployment` / `--existing-installation`) is always explicit. Owners: 999 (MariaDB's mysql) and 82
  (www-data); never `chmod 777` or recursive changes, never change the
  mountpoint's `root:root` 0755. `docker/storage/preflight.sh` stays
  read-only; `tests/Unit/Deployment/PersistentStorageTest.php` enforces it.
  Production restart policies stay `"no"`: the dedicated
  `digital-library.service` (preflight, then `up --no-recreate --no-build
  --pull never`) is the only boot path. Never modify `docker.service` or
  make other Docker workloads depend on this disk.
- Backups/restore/maintenance/cleanup are CLI-only (`Console\Operations`).
  Operations commands are listed in `Console::OPS_COMMANDS` (ops role only
  in production, never `APP_ROLE=web`) and, when they must not overlap, in
  `Console::EXCLUSIVE_COMMANDS` (`OperationLock`); add new ones there. Never
  describe a restore as atomic; keep the safety backup, restore marker and
  literal-only INSERT validation.
  Destructive operations are dry-run or guarded by default; never add web
  routes for them. Tests restore only into the disposable test database
  and temporary directories.
- Cover files are only ever reached through `CoverImageProcessor::path()` /
  `delete()`, never by building paths from input.

## Commands

```bash
docker compose up -d --wait
docker compose exec php php bin/console migrate
docker compose exec php vendor/bin/phpunit --fail-on-skipped   # all tests
docker compose exec php vendor/bin/phpunit --testsuite unit
docker compose exec php composer lint
```

Without Docker, unit tests run with a local PHP ≥ 8.3: `composer install && vendor/bin/phpunit --testsuite unit`.

## Mandatory infrastructure access restriction

Only the repository owner is authorized to access servers
and production infrastructure.

Claude must never connect to, inspect, probe, modify, or
execute commands on remote infrastructure, even when
credentials or network access are available.

Claude may prepare diagnostic scripts and deployment
instructions, but only the owner may execute them.

Claude may analyze sanitized outputs explicitly provided
by the owner.

Before any infrastructure-related task, follow:
`.claude/skills/infrastructure-access-boundary/SKILL.md`

This restriction applies to all tools, agents, delegated
tasks, and future sessions.
